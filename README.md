# 停车缴费码 (ParkQR)

装在安卓车机上。打开就显示**离你最近的那个停车场**的缴费二维码 + 车牌，
用手机扫车机屏幕上的码去付款。

面向 1920×720 这类宽屏车机做了左右分栏（二维码占满屏高），竖屏/方屏自动退回上下布局。

## 为什么是这个设计

- **二维码分两种，都支持。** 大部分停车场缴费物料码是标准 QR，扫出来是一段 URL。
  这种只存文本，显示时用 zxing 按屏幕尺寸重绘，任意大小都清晰。少数是微信小程序码
  （圆形花瓣状，不是 QR），标准解码器读不出，就按原图存。上传时自动判断。
- **传码走 HTTP，不走蓝牙。** 车机 ROM 的蓝牙 API 限制多、BLE 传图慢、配对麻烦。
  车机上起一个 HTTP server，手机连同一个 WiFi（或车机热点）用浏览器传，手机端零开发。
- **位置由车机自己采。** 手机浏览器在明文 http 页面下是非安全上下文，Chrome 直接禁用
  Geolocation API，拿不到定位；而且你人就在停车场，车机 GPS 更准。
- **地库没 GPS。** App 在前台时持续记录定位并把最新的一个落盘，所以进了地库、
  甚至冷启动，拿到的仍是**开进车库入口前的最后一个有效点**。
- **不依赖 GMS。** 车机普遍没有 Google 服务，定位一律走 `LocationManager`，
  没有用 FusedLocationProvider。

## 用法

### 1. 车牌

车牌是全局的，不绑停车场，支持多个。主界面点车牌行：单选切换、添加、删除、复制。

### 2. 录入一个停车场

到了停车场 → 打开 App → 「管理」→「＋ 新建」，填名称，点「记录当前位置」
（在露天/入口处成功率最高，进了地库就收不到星了）。

### 3. 把缴费码传进来（三条路）

「管理」→「手机传码」。车机屏上出现**入口码**（注意它只是打开上传页的入口，不是缴费码）：

- 手机连**车机热点**（或同一 WiFi）→ 微信「扫一扫」扫入口码 → 打开上传页；
- **方式一（推荐）**：微信扫停车场物料码，复制打开的链接，粘贴到上传页——不用拍照；
- **方式二**：直接传一张物料码照片，能解码就存文本，解不出（小程序码）存原图；
- **兜底**：车机上「管理」→ 点停车场 →「手动输入码内容」，直接输/粘 URL。

服务只在对话框打开期间运行，关掉就停。

### 4. 平时用

打开 App，它会按距离排序自动选中最近的那个停车场，直接显示码。
不对就点「切换停车场」。点车牌那一行可以复制车牌，方便在缴费页面里粘贴。

## 构建

```bash
./gradlew :app:assembleDebug
```

需要 JDK 17（`JAVA_HOME=$(/usr/libexec/java_home -v 17)`）和 Android SDK 34。
产物在 `app/build/outputs/apk/debug/app-debug.apk`，`adb install -r` 装到车机即可。

跑设备上的测试（覆盖二维码编解码、反色、旋转、存储、距离计算）：

```bash
./gradlew :app:connectedDebugAndroidTest
```

## 数据

都在 App 私有目录，不上传任何地方：

- `files/lots.json` — 停车场列表（名称、车牌、经纬度、码文本、备注）
- `files/qr/*.png` — 解不出内容的物料码原图
- `shared_prefs/geo.xml` — 最后一个有效定位

## 预设数据格式（欢迎 PR 你所在城市）

文件放在 `presets/<city>.json`：

```json
{
  "city": "深圳",
  "coord": "wgs84",
  "source": "数据来源说明",
  "license": "许可（如 ODbL — © OpenStreetMap contributors）",
  "lots": [
    { "name": "某某停车场", "lat": 22.5361, "lng": 113.9345, "note": "地下 收费" }
  ]
}
```

- `coord` 声明坐标系：`wgs84` / `gcj02`（高德、腾讯）/ `bd09`（百度），App 导入时自动转 WGS-84
- `note` 可选
- `payload` 可选：该停车场缴费物料码的**文本内容**（微信扫物料码得到的链接）。
  物料码本身公开贴在停车场，欢迎扫码后把内容 PR 进来让预设自带码；
  注意运营商更换或改版后码会失效，发现失效请提 PR 更新。
  没有 `payload` 的场导入后显示"缺码"，用户到场后用手机传码补

从 OpenStreetMap 生成任意城市数据（把城市名换掉即可）：

```
[out:json][timeout:90];
area["name"="深圳市"]["boundary"="administrative"]->.a;
nwr["amenity"="parking"]["name"](area.a);
out center 8000;
```

POST 到 `https://overpass-api.de/api/interpreter`，把结果转成上面的格式
（OSM 坐标就是 WGS-84）。`presets/shenzhen.json`（157 个）即由此生成，
数据 © OpenStreetMap contributors, ODbL。

### 关于 HTTPS

手机浏览器提示"不安全"是因为传码走的是局域网明文 http。这里**不适合上 HTTPS**：
Let's Encrypt 不给私网 IP 签证书；自签证书会让浏览器弹出更吓人的整页拦截警告
（微信内置浏览器可能直接拒绝），体验更差。传输只发生在你的车机和手机之间，
内容是停车场名和缴费码链接，风险可忽略。

## v1.7.0 新增

- **永远距离优先**：不再因为"有没有码"跳过更近的停车场。之前会出现"脚下 500 米
  的场没码，就跳去 3.6 km 外那个有码的"。手动点选的场只在本次会话粘住，
  「刷新定位」会清掉重算。
- **候选条含无码场**：三个候选按距离排，没码的标 ▲缺码，点一下直接进传码流程。
- **主区一键传码**：没码时，二维码位置直接可点 → 打开手机传码并预选该场。
- **后台定位（前台服务）**：每分钟记录一次位置并落盘，App 切到后台也照记。
  这样开进地库、停好车再回来时，即便收不到卫星信号，也能用"进地库前最后一个点"
  匹配到正确的停车场。「管理」→「后台定位」可开关，「自启诊断」里能看到最后记录时间。

## v1.7.1 修复/新增

- **前台自动刷新（bug 修复）**：此前定位监听只把新坐标缓存起来，从不通知界面重绘，
  所以 App 摆在前台距离也不动，只有手点「刷新定位」才更新。现在拿到新定位立刻重算
  并重选最近的场，另加 15 秒定时兜底；二维码内容没变时不重绘，避免扫码时闪烁。
- **中国车牌样式**：省+字母后 5 位显示蓝牌（深蓝底白字），6 位显示新能源渐变绿牌
  （白→绿、黑字），并加圆点分隔符。

## 已知边界

- 打开 App 时若从没拿到过定位，会先显示"无坐标"，等 GPS 定上后重进一次即可。
- 行驶中弹全屏二维码有安全隐患，正式上车前建议加个车速/挡位判断（需要车机的车辆信号接口）。
